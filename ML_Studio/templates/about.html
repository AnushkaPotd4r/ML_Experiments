About ML Studio: Project Architecture & Viva Guide

Academic project background, end-to-end architecture, and foundational viva-voce technical questions.

Project Overview & Academic Objective

ML Studio is an interactive educational machine learning laboratory designed for engineering students and data science practitioners. It aggregates 10 foundational supervised machine learning algorithms (2 regression models and 8 classification models) into a centralized, responsive dashboard.

Every single algorithm runs on top of genuine Scikit-learn pipelines with actual train-test partitioning (80/20 or 75/25), automated standard feature scaling to prevent data leakage, metric evaluations (R², MAE, MSE, Accuracy, Precision, Recall, F1, Confusion Matrices), and interactive visualization generation (Matplotlib headless Agg and Chart.js).

Python 3.13 Flask 3.1 Scikit-learn 1.7 Pandas & NumPy Matplotlib & Seaborn Chart.js Visualizations SQLite History Database

Viva Voce & Examination Preparation Guide

Q1: What is the mathematical difference between Simple and Multiple Linear Regression?

Simple Linear Regression relates one continuous predictor x to target y via y = β₀ + β₁x + ε (a straight 2D line). Multiple Linear Regression fits a hyperplane across p predictors: y = β₀ + β₁x₁ + β₂x₂ + ... + βpxp + ε using vector matrix notation y = Xβ + ε solved via normal equations β = (XTX)-1XTy.

Q2: Why can't we use standard Linear Regression directly for binary classification?

Linear regression produces unbounded continuous values (−∞, +∞), violating the axiomatic probability interval [0, 1]. Furthermore, its squared residual error penalizes highly confident correct predictions arbitrarily, shifting the decision boundary when outliers exist. Logistic regression fixes this by compressing the linear output through the sigmoidal link function σ(z) = 1 / (1 + e-z).

Q3: What is the "Kernel Trick" in Non-Linear Support Vector Machines?

The Kernel Trick enables linear algorithms to learn non-linear boundaries by mapping input data into higher-dimensional feature space Φ(x) without ever explicitly calculating the coordinates in that space. Instead, the dot product ⟨Φ(x), Φ(z)⟩ is computed directly in the original space via kernel functions such as the Radial Basis Function (RBF) K(x, z) = exp(-γ||x - z||²).

Q4: How does Random Forest resolve the high-variance limitation of individual Decision Trees?

Single deep decision trees suffer from high variance (overfitting). Random Forest resolves this via Bagging (Bootstrap Aggregation): it creates B bootstrapped datasets and introduces feature randomness by selecting a random subset of √p features at each candidate split. Averaging predictions across these decorrelated trees dramatically reduces overall variance while preserving low bias.

Q5: Why is Feature Scaling essential for KNN and SVM, but not for Decision Trees?

KNN and SVM rely on geometric distance metrics (Euclidean distance or margin width). Features with large raw scales (e.g., IQ: 100) will overpower features with small ranges (e.g., CGPA: 8.0) unless standardized with StandardScaler. In contrast, Decision Trees evaluate splits on individual features monotonically one at a time, making them scale-invariant.
